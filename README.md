# 任务空间

本地只读 Codex 项目与任务浏览器，提供项目卡片、任务卡片、需求与输出详情、全文模糊搜索和 Markdown 导出。不依赖 Obsidian、外部字体或在线服务。

## 页面与使用

1. 首页网格只展示在 Codex 中创建的项目卡片，点击查看项目下的主任务。卡片只保留项目名称和任务数量，不显示说明、图标或箭头，桌面高度约 128px、移动端约 112px；历史目录不再单独生成项目卡片，未关联当前项目的主任务统一放进“已归档”，通过标题右侧带数量的独立入口查看，不与项目卡片混排。
2. 只有用户发起的 Codex 对话展示为任务卡，项目卡片和页脚按同一口径计数。任务卡片（含搜索结果）只保留任务名称、需求轮数和输出数量，不显示图标、摘要、箭头及其他标签，沿用项目卡片的紧凑高度；完整正文检索与命中定位仍保留。点击进入详情，按轮次逐一显示左侧需求、右侧对应输出；子任务与审查任务收在主任务详情的折叠区域，展开后按需读取完整正文。
3. 顶部搜索在本机服务端检索全部项目名、任务标题、完整需求和输出，含归档与子任务，不受摘要或当前展示页数限制。支持中文片段、邻近跳字、多关键词以及英文大小写归一化；同一主任务及其子任务命中后合并为一张主任务卡片，点击可展开命中的子任务并定位对应轮次，按 Esc 或清除按钮退出搜索。
4. 面包屑、浏览器前进/后退和详情地址刷新均可使用。宽屏为三列卡片与双栏详情，窄屏自动改为单列。
5. 项目页右侧的“导出”菜单支持导出整个项目，或选择一个/多个任务后导出为一个 Markdown 文件。只有选择模式显示复选框与选择栏；“全选本项目”包含尚未加载的任务。默认只导出主任务，可勾选“包含子任务与审查”并归入各自主任务。“已归档”集合使用相同操作。
6. 任务详情中，每轮标题右侧的“导出本轮”可单独下载该轮原始需求与全部对应输出，文件保留项目、任务和原始轮次编号。展开的子任务与审查轮次也可使用；不会混入其他轮次。

首页不显示“归类 / 读取说明”横幅；正文不可用或读取失败仍在相关详情及失败状态中提示。搜索中的归档集合也使用独立入口，不生成项目卡片。界面提供以上展示、检索与 Markdown 导出，不提供创建、编辑、导入、版本管理、交接或验收入口。旧的领域服务及数据仍保留兼容，没有迁移或删除。

导出保留全部轮次、原始需求和明确最终输出，不受卡片分页或详情折叠影响。每轮使用 `> [!note] 第 N 轮` Callout 卡片，将需求与对应输出放在一起，轮次之间用分隔线区分；项目、所选任务和单轮导出均使用此格式。正文仅增加卡片引用前缀，原有 Markdown、代码缩进、表格和链接保留。此格式兼容 Obsidian 实时预览与阅读视图；编辑卡片内容时会按编辑器行为展示源码，光标移出卡片后恢复预览。不支持 Callout 的阅读器仍可作为普通引用块阅读，但可能显示 `[!note]` 标记；边框与底色由阅读器决定。每份文件使用同一个内存快照并标注读取时间。空任务或无最终输出会明确标记；所选任务正文读取失败时会报告错误，不静默跳过。文件通过浏览器下载，不在服务端保存副本、不打包附件，工作台无需安装或连接 Obsidian。

## 展示数据

直接只读连接当前用户的 Codex 原生数据目录（默认 `%USERPROFILE%\.codex`，配置 `CODEX_HOME` 时以其为准）。读取 `state_5.sqlite` 中项目/线程、`.codex-global-state.json` 中明确归属，以及 `thread_history_1.sqlite` 中的需求/最终输出；SQLite 连接使用 `readOnly: true`。

项目卡片以 Codex 当前项目表为准，不从旧状态恢复已删除项目；缺少项目表的旧版本才回退到本机保存的项目列表。任务优先采用原生或明确项目归属，没有明确归属时匹配当前项目的工作目录；明确无项目、归属已删除项目或无法匹配的主任务统一收进“已归档”。子任务与审查任务跟随主任务，当前零任务项目仍展示。“已归档”是工作台的展示集合，不改变 Codex 原生记录的 `archived` 状态。

正文按线程、轮次与消息身份配对；旧存储版本的别名合并到同一对话。先读取原生投影，落后的未压缩日志只补读尾部；无投影时支持 JSONL / `.jsonl.zst` 流式回退。所有明确 `final` / `final_answer` 均保留，不把 commentary、推理或工具日志冒充最终结果。图片附件保留占位与文件名，不做 OCR，也不把图片 base64 送入搜索。

项目与任务数量根据当前用户的本机数据计算，实际读取时间和任务数见页脚。子任务和审查任务仍完整读取，但不计入项目或任务卡片数量；Codex 原生归档的用户任务也保留。已读取但没有消息的空任务与正文读取失败分别处理，不注入示例数据。

程序只在内存缓存全文索引，普通请求至多每 5 秒检查一次源文件变化；页脚刷新按钮立即检查。不存在定时后台采集或对话自动执行。原始 Codex 数据、认证文件与旧工作台数据库均不会因本机浏览而导入、覆写或迁移；不读取 `auth.json`。当前适配本机已验证的原生数据库版本，结构变化或读取失败会显式报错。

## 启动与停止

主要面向 Windows，需要 Node.js 24.13–24.x，以及本机已有的 Codex 项目与对话数据。克隆仓库后，在项目目录按顺序运行：

```powershell
npm ci
npm run build
.\scripts\Start-Workbench.ps1
```

访问 http://127.0.0.1:43127 。双击 `Stop-Workbench.cmd` 停止服务。

首次安装与构建完成后，可直接双击 `Start-Workbench.cmd` 启动。默认数据目录为 `%LOCALAPPDATA%\CodexTaskWorkbench`；服务仅监听本机地址。启动脚本复用同目录服务，不注册开机启动。Node 的 SQLite 实验性提示不影响已验证的启动和读取。

## 开发与验证

```powershell
npm run typecheck
npm run build
npm test
```

开发时运行 `npm start` 启动 API，再运行 `npm run dev`。

默认测试使用独立临时目录和合成数据。历史导入另有一项可选的本机样本验证，仅在显式设置 `WORKBENCH_SAMPLE_MANIFEST` 为样本清单路径时运行；未设置时明确跳过。仓库不包含真实对话、数据库、导出文件或测试截图，`evidence/`、`web/evidence/` 与运行目录均已排除。

- `web/src/viewer/Viewer.tsx`：三层浏览、URL 导航、搜索界面。
- `web/src/viewer/Content.tsx`：需求与输出的安全文字/Markdown 展示。
- `web/src/native-api.ts`：本机目录、按需详情、完整搜索和 Markdown 导出的 HTTP 客户端。
- `web/src/viewer/task-groups.ts`：用户任务口径、父子任务归属和搜索结果归并；不按标题或时间猜测父任务。
- `server/native/catalog.ts`：只读项目目录、明确归属、父子任务及工作目录映射。
- `server/native/history.ts`：原生历史、存储别名、JSONL/zst 回退、需求与最终输出配对。
- `server/native/service.ts`：内存索引、摘要目录、全量模糊搜索及命中轮次、同快照导出范围校验。
- `server/native/markdown.ts`：完整需求与输出的 Markdown 排版及下载文件名。
- `shared/native-contracts.ts`：本机只读浏览的独立协议，旧协议保持兼容。
- `web/src/styles.css`：统一网格、视觉对齐、响应式与键盘焦点。
- `tests/native-*.test.ts`：只读原库、归属、覆盖、分页/回退、跨轮配对和 HTTP 安全验证。

原有 HTTP 接口文档见 `server/API.md`，历史导入格式边界见 `server/history/README.md`。本次界面改版没有新增依赖或变更数据库结构。
